🦾 placo_ik 安裝流程與依賴說明

把 placo_ik_main.py 打包到其他 x86_64 PC（ROS 2 Humble / Python 3.10）

🐧 Ubuntu 22.04 🤖 ROS 2 Humble 🐍 Python 3.10 📦 placo 0.9.20 🔢 numpy 2.2.x

本文件說明兩種安裝路徑、實際會裝進哪些依賴，以及打包到別台機器時必須注意的版本約束與 ROS 通訊設定。所有檔案都在 placo_ik/deploy/ 目錄。

🧭兩種安裝路徑

推薦

🐳 路徑 A：Docker

依賴全部烤進 image，裝一次、之後秒進，環境完全隔離、可重現。已內建跟本機 ROS 2 通訊所需設定。

# 第一次會 build image（約 1–2 分鐘）
cd placo_ik/deploy
./shell.sh
替代

⚙️ 路徑 B：直接裝在本機

適合該機已有 ROS 2 Humble、想把依賴直接裝進系統 Python 的情況。

cd placo_ik/deploy
./install_deps.sh   # apt + pip
./verify_deps.sh    # 煙霧測試

🔄安裝流程

路徑 A（Docker）在 build 時跑步驟 1–3，shell.sh 進場即用；路徑 B 用 install_deps.sh 跑 1–3、verify_deps.sh 跑 4。

📦會安裝哪些依賴

依賴分三層，由下而上堆疊：

🟦 A 層 · APT（系統） ROS 2 Humble 的訊息型別與 tf2 Python binding。rclpy 雖隨 ros-base，仍顯式列出以防最小映像缺漏。
python3-pip ros-humble-rclpy ros-humble-geometry-msgs ros-humble-sensor-msgs ros-humble-std-msgs ros-humble-trajectory-msgs ros-humble-tf2-ros-py
🟩 B 層 · PIP（科學運算） 腳本直接 import 的數值 / 繪圖 / 設定檔套件。
numpy >=2.2,<2.3 scipy matplotlib PyYAML
🟪 C 層 · placo + cmeel 子樹 IK 求解核心。皆為預編譯 binary wheel，整組鎖版本（原因見下方「關鍵約束」）。
placo==0.9.20 pin==3.8.0 libpinocchio==3.8.0 coal==3.0.2 libcoal==3.0.2 eigenpy==3.12.0 eiquadprog==1.3.0 cmeel==0.60.1 cmeel-boost==1.89.0 cmeel-urdfdom==4.0.1 cmeel-tinyxml2==10.0.0 cmeel-console-bridge==1.0.2.3 cmeel-octomap==1.10.0 cmeel-qhull==8.0.2.1 cmeel-assimp==6.0.5 cmeel-zlib==1.3.2 rhoban-cmeel-jsoncpp==1.9.4.9 meshcat==0.3.2 ischedule==1.2.7

⚠️關鍵約束（打包到別台必看）

① numpy 必須是 2.2.x，不能 <2。
依賴鏈 placo 0.9.20 → pin 3.8.0 → cmeel-boost 1.89.0 在 cp310 硬性要求 numpy>=2.2,<2.3。若強壓 numpy<2，pip 會回報 ResolutionImpossible。下界寫 >=2.2 也是為了逼 pip 升級掉系統 apt 內建的舊 numpy。
② placo 的 cmeel 子樹要整組鎖死。
這些是預編譯 .so，彼此以 soname 連結（例如 liburdfdom_sensor.so.4.0、libtinyxml2.so.10）。 而 placo/pin 只宣告鬆約束（>=4 之類），全新解析會抓到 soname 更新的 wheel，造成 import placo 報 lib<x>.so.<n>: cannot open shared object file。 鎖整組就能保證 soname 對齊。
③ FastDDS 跨容器通訊：容器要以本機 UID 跑。
Humble 預設 RMW 是 rmw_fastrtps_cpp，透過 /dev/shm 的 per-UID 共享記憶體段做 discovery。 root 容器建的段是 0644，本機使用者（uid 1000）寫不進去 → discovery 靜默失敗、ros2 topic echo 只會 timeout。 shell.sh 已自動加 --user $(id -u):$(id -g) 解決。
🗂️ URDF 不是依賴、是資料。 placo 載入前會把 URDF 的 <visual> / <collision> 全部剝掉，所以不需要帶 meshes，只要一個 .urdf 檔。Docker image 已預設 OPENARM_URDF=/work/openarm_ros2/placo_ik/ik_solver/v10_o6.urdf；裝在本機時請自行 export OPENARM_URDF=/path/to/openarm.urdf。

✅驗證與通訊測試

依賴煙霧測試（不需硬體）

verify_deps.sh 會逐一 import 全部第三方套件，再用 --help 跑過整條 import chain：

==> [verify] importing third-party deps
   ok   numpy / scipy / matplotlib / yaml / placo
   ok   rclpy / geometry_msgs / sensor_msgs / std_msgs / trajectory_msgs / tf2_ros
==> [verify] ALL CHECKS PASSED

在乾淨容器驗證安裝腳本

cd placo_ik/deploy
./test_docker_humble.sh   # 全新 ros:humble 容器跑 install + verify

本機 ROS 2 通訊測試（已實測通過）

容器端發 topic、本機端訂閱，確認 discovery 打通：

# A 終端：容器發 topic
./shell.sh ros2 topic pub /ping std_msgs/msg/String "{data: hi}" -r 5

# B 終端：本機收
export ROS_DOMAIN_ID=10
ros2 topic echo --once /ping        # → data: hi
實測結果：容器（以 uid 對齊）→ 本機 ros2 topic echo 成功收到訊息。若 echo 噴 xmlrpc Fault: !rclpy.ok()，那是本機 ros2 daemon 壞了，跑 ros2 daemon stop 重啟即可，與容器無關。

▶️實際執行 profiler

./shell.sh                                  # 進容器，落在 ik_node/
# 容器內：
python3 ./placo_ik_main.py --arm right
執行 IK 時仍需本機有在跑 robot driver，且 tracker 在發 /ee_delta/{arm}。 --help 不需要這些；通訊管道本身已驗證 OK。RMW 若改 cyclonedds，用 RMW=rmw_cyclonedds_cpp ./shell.sh 對齊。
